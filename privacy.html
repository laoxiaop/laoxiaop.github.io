In one sentence: Health Data Tracker reads the owner's own Google Health data with read-only permission, keeps it on the owner's own computer, shares it with nobody, and never uses it for advertising, profiling, AI training, or any kind of synthetic or non-consensual intimate imagery.

1. Who this policy is about

Health Data Tracker ("the application") is a private, single-user software tool built and operated by one individual ("the owner", "I", "we") for their own personal use. The application has exactly one user — its owner. It is not a commercial product, is not offered to the public, does not accept registrations, and has no users other than the owner.

This policy explains what data the application handles, where it comes from, what it is used for, where it is stored, who it is shared with (nobody), and how it is deleted. It applies to the application and to this website (laoxiaop.github.io).

2. What data is collected

2.1 Google user data

The application can read the owner's own data from Google's health service through the Google Health API, using OAuth 2.0. It requests only the four read-only permissions listed below, and it reads only the data those permissions cover — nothing else.

ScopeData typesPurpose
googlehealth.activity_and_fitness.readonly Daily and intraday activity: step count, distance, calories burned, active minutes, floors, exercise sessions and their type/duration Activity and exercise trend charts
googlehealth.health_metrics_and_measurements.readonly Body measurements and health metrics recorded by the owner's own devices or entered by the owner: heart rate, weight, body fat and other body composition values, and similar measurements Charts of measured values over time, placed next to the owner's own medical test results
googlehealth.sleep.readonly Sleep sessions, sleep stages, sleep duration and timing Sleep duration and timing charts
googlehealth.location.readonly Location samples attached to the owner's own exercise sessions (workout routes) Showing the route and distance of the owner's own workouts

The application does not request or access Gmail, Contacts, Calendar, Drive, Photos, YouTube, or any other Google service. It does not request the owner's name, email address or Google account profile.

2.2 Data the owner records directly

The owner also keeps their own medical test results, medication notes and symptom notes in the same local workspace. Those files are created and owned by the owner and are handled exactly as described in sections 4–6.

2.3 Data this website collects

None. This website is static HTML. It sets no cookies, runs no analytics, contains no advertising or tracking scripts, and has no forms. The hosting provider (GitHub Pages) may keep standard web server access logs, as any web host does; those logs are not available to the application and contain no health data.

3. How the data is obtained and authorised

  • Authorisation happens once, on Google's own OAuth consent screen, where the owner sees each permission and approves it. Declining any permission means the application simply cannot read that data type.
  • The OAuth 2.0 access and refresh tokens are issued by Google and stored in the Windows Credential Manager on the owner's computer — never on a server, never in this repository, and never in a plaintext file.
  • The owner can revoke access at any time at myaccount.google.com/permissions. Revocation takes effect immediately: the application can no longer read any Google data.
  • The application never asks for the owner's Google password, and it never sees one.

4. How the data is used

Google user data obtained through the above permissions is used only to:

  • store a local, personal copy of the owner's own health history;
  • produce trend charts, longitudinal summaries and a local dashboard for the owner's own review;
  • let the owner compare their own wearable data with their own medical test results when preparing for a doctor's appointment.

It is not used to:

  • sell, rent, license, trade or transfer data to anyone;
  • advertise, market, profile, score or make automated decisions about any person;
  • determine eligibility for credit, insurance, employment, housing or healthcare;
  • train, fine-tune, evaluate or improve any AI or machine-learning model, whether the owner's own or a third party's;
  • generate, edit or distribute any synthetic media — and specifically never to create or distribute AI-generated non-consensual intimate imagery (AI NCII) or any other sexual or intimate content, real or synthetic.

5. Storage and location

  • All data is stored locally on the owner's own computer, in a database file (health.db) and exported copies (CSV / Parquet / original JSON) in the owner's own private folder.
  • There is no cloud backend, no server, no remote database and no hosted copy. The application has no server-side component at all.
  • No data is synchronised to cloud drives, file-sharing services, note apps or third-party storage.
  • Data is not transferred internationally by the application, because it does not leave the owner's device.

6. Sharing and disclosure

No sharing. The application does not sell, rent, share, transfer, publish or disclose Google user data, or any other personal data, to any third party — including service providers, contractors, advertisers, analytics vendors, data brokers or affiliates. There are no third-party SDKs, no telemetry, no crash reporting and no remote logging. The only person who can read the data is the owner.

The only exception would be a disclosure required by applicable law, and because the data never leaves the owner's device, no such disclosure mechanism exists in the application.

7. Google API Services User Data Policy — Limited Use

Health Data Tracker's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. In particular:

  • Google user data is used only to provide the user-facing features described in section 4;
  • it is not transferred to third parties except as necessary to provide those features (in practice: never), or for security/legal compliance, or as part of a merger with prior consent;
  • it is not used for advertising, and is not sold;
  • it is not used to train or improve generalised or non-personalised AI/ML models, and no human reads it other than the owner.

8. Retention and deletion

8.1 Retention

Data is kept locally only for as long as the owner wants to keep their own history. There is no automatic expiry, because the point of the tool is a long-term personal record.

8.2 How to delete everything

  1. Delete the local data: remove the application's data folder (including health.db and exported files) from the owner's computer. Deletion is immediate and permanent; the application keeps no backup copy anywhere else.
  2. Revoke Google access: at myaccount.google.com/permissions, remove Health Data Tracker. This invalidates the stored tokens at Google's side; any further API call fails.
  3. Clear stored credentials: remove the application's entry from Windows Credential Manager, so no token remains on the device.
  4. By email: send a deletion request to tol_43@163.com. Because the owner is the only user and the data is not held on any server, a request is confirmed and completed within 30 days; in practice there is nothing remote to delete, and the request is answered with confirmation and step-by-step local deletion instructions.

Note that Google retains its own copy of the owner's health data in the owner's Google Account; deleting data from this application does not delete it from Google. That data is governed by Google's Privacy Policy and can be managed in the owner's Google Account.

9. Security

  • All communication with Google uses HTTPS/TLS; the application does not accept plaintext connections.
  • OAuth tokens live in the operating system's credential store, not in project files.
  • Data at rest is protected by the device's own access controls (Windows account login, disk encryption if enabled, physical control of the machine).
  • The application is not exposed to the internet: it has no listening server, no public endpoint and no remote access path.
  • Because no data is stored server-side, there is no server-side data breach surface for this application.

10. Children

The application is not directed to children and is not used by anyone other than its adult owner. It does not knowingly collect data from children under 13 (or the minimum age in the owner's jurisdiction).

11. The owner's rights

The owner can, at any time and without asking anyone: view all stored data (it is local), export it, correct it, delete it, and revoke the application's Google access. Since the owner is the data subject and the only operator, these rights are exercised directly; the contact address below is available for any question or request.

12. Changes to this policy

If the application's data handling changes, this page is updated and the "Last updated" date at the top changes with it. The current version is always the one published at laoxiaop.github.io/privacy.html.
